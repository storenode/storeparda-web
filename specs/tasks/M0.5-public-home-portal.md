# M0.5 — Public home portal

**Status:** Completed
**Est:** 6 hrs (Constitution §5, v1.1.0 amendment)

Public-facing landing page shown by default when a user or customer opens StoreParda
before signing in. Shows the brand, a short pitch, and a Google Sign-In entry point.
The Google Sign-In **handler** (OAuth wiring, session creation, redirect handling) is
out of scope here and lands with M1 (Constitution §5) — this task only ships the UI.

## Definition of Done

- [x] New public route (`/`) renders the portal page to unauthenticated visitors,
      distinct from the authenticated app shell (`AppShell`/tab bar, now under `/app`)
- [x] Page shows brand mark, tagline, short pitch copy
- [x] "Sign in with Google" button present and visibly styled per brand colors
      (`#2FBF71` green / `#7B7FE0` lavender) — click handler is a stub/no-op until M1
      wires real OAuth
- [x] Responsive at 375px, no horizontal scroll, tap targets ≥ 44px
- [x] Route split from the authenticated shell (`/` vs `/app/*`) — real auth-state guard
      still a stub until M1 ships actual sessions
- [x] `pnpm build`, `pnpm typecheck`, `pnpm test` all green

## What shipped

- **Hero** with a layered parallax background (gradient + blurred brand-color blobs +
  an abstract awning-stripe motif, each layer scrolling at a different rate off `scrollY`)
- **Features section** — 6 cards pulled from `data/features.ts`
- **Selling-points section** — 3 value props pulled from `data/sellingPoints.ts`
- **CTA banner** + **footer**
- **Navbar**: transparent over the hero, switches to a solid/blurred surface once
  scrolled past ~70% of viewport height
- **Light/dark theme**: `ThemeProvider` (`src/components/theme/`) drives a `data-theme`
  attribute + CSS custom properties (`src/index.css`); toggle in the navbar; persisted
  to `localStorage`; an inline script in `index.html` sets the attribute pre-hydration
  to avoid a flash of the wrong theme
- **Fonts**: Inter (body), Plus Jakarta Sans (headings/`font-display`), Dancing Script
  (logo wordmark/`font-script`) — all Google Fonts, loaded in `index.html`
- **Component structure**: `components/ui/` (Button, Container) for generic primitives,
  `features/home/components/` for page sections, `features/home/data/` for editable
  content arrays kept separate from JSX (features, selling points) so copy changes
  don't require touching component code

## Routing change

`src/router.tsx` restructured: `/` is now the public `HomePage`, and the previously
root-mounted `AppShell` (bill/inventory/trips/reports/settings) moved to `/app/*`.
`AppShell`'s nav links updated to `/app/...` accordingly.

## Verified

`pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test:cov` all pass (91.3% `src/lib`
coverage, unaffected by this change). Manually driven with Playwright against the dev
server: light + dark screenshots at desktop and 375px mobile widths, scroll-triggered
navbar transition, `/app/bill` route — zero console errors.

## Notes

- This inserts ahead of M1 in the roadmap because the portal is the first thing any
  visitor sees, before any auth flow exists.
- Constitution amended to v1.1.0 to add this module and extend M1's auth scope from
  phone-OTP-only to phone OTP + Google Sign-In — see `specs/constitution.md` §8 changelog.
- Fonts load from Google's CDN, which is a soft break from offline-first purism for the
  *public* portal specifically (the authenticated `/app` shell doesn't depend on it).
  Self-hosting the font files is a reasonable follow-up if that matters before pilot.
